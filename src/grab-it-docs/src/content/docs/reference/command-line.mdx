Run Grab-it with `--open` and a target to open a window or start a capture straight away. It works whether or not Grab-it is already running: a second launch hands its `--open` to the running Grab-it and quits. That makes it handy for a desktop shortcut, a script, a launcher like Raycast or Alfred, or a desktop without a tray.

```sh
grab-it --open region
grab-it --open=library
grab-it --open editor ~/Pictures/Grab-it/shot.png
```

Launching Grab-it again with no `--open` opens the Library.

## Targets

| Target | What it does |
| --- | --- |
| `settings` | Opens Settings |
| `library` | Opens the Grab-it window on the Library |
| `welcome` | Opens the welcome: what Grab-it does and its hotkeys |
| `region` | Starts a region capture |
| `all-in-one` | Opens **Capture & record…** |
| `repeat` | Captures the last dragged region again |
| `text` | Starts Capture text: drag over text to copy it |
| `colour` (or `color`) | Starts the colour picker |
| `record` | Starts a recording, or stops the one under way |
| `steps` | Starts a [step capture](/grab-it/capture/step-capture/), or stops the one under way and opens its guide |
| `editor <file>` | Opens a capture in the image editor |
| `quick <file>` | Shows a capture on the Quick Access card |
| `pin <file>` | Pins an image above other windows |
| `guide <file>` | Opens a step capture's `.guide.json` in the Guide window |

`editor`, `quick`, `pin` and `guide` need the file to open, such as `--open pin shot.png`. If the file doesn't exist, nothing opens.

Grab-it ignores other arguments, and prints a message (on the terminal it was started from) for an unknown target or a missing file.

## Commands

The commands ask the running Grab-it to list your displays and windows, take a screenshot, record the screen, or make a GIF or contact sheet of a video, and print the result as one line of JSON. They're made for [AI agents](/grab-it/ai/agents/) and scripts. Turn on **Settings → AI integration → Let AI agents use Grab-it** first: while it's off, every command fails with a message saying so.

If Grab-it isn't running, a command starts it in the tray and waits up to 15 seconds for it. Errors go to stderr, with exit code 1 when Grab-it couldn't do what was asked and 2 for a mistake in the command itself.

| Command | What it prints |
| --- | --- |
| `grab-it displays` | `{"displays":[…]}`: each display's `id`, `name`, `x`, `y`, `width`, `height`, `scaleFactor` and `primary` |
| `grab-it windows` | `{"windows":[…]}`: each window's `id`, `app`, `title`, `x`, `y`, `width` and `height`, front to back |
| `grab-it shot` | `{"path":…,"width":…,"height":…,"id":…}`: the saved PNG, its size in pixels and its Library item |
| `grab-it record` | `{"path":…,"format":…,"recording":true}` as it starts, or with `--for`, `{"path":…,"durationMs":…,"format":…,"id":…}` once it's saved |
| `grab-it stop` | `{"path":…,"durationMs":…,"format":…,"id":…}`: the recording it ended, once it's saved |
| `grab-it gif <video>` | `{"path":…,"width":…,"height":…,"durationMs":…,"id":…}`: the GIF it made |
| `grab-it frames <video>` | `{"path":…,"width":…,"height":…,"frames":…,"id":…}`: the contact sheet it made |
| `grab-it help` | Every command and option |

```sh
grab-it windows
# {"windows":[{"id":4194307,"app":"Firefox","title":"Docs","x":0,"y":25,"width":1280,"height":800}]}
grab-it shot --window firefox --max-width 1280
# {"path":"/home/me/Pictures/Grab-it/originals/2026-11-17 09-00-00.png","width":1280,"height":800,"id":42}
```

Rectangles are in desktop coordinates, the same ones `--region` takes.

### What `shot` and `record` capture

Give one of these; with none, `shot` captures every display and `record` the main one.

| Option | Captures |
| --- | --- |
| `--screen` | Every display, stitched into one image. A recording is of one display, so `record` takes the main one. |
| `--display <id or name>` | One display: an `id` from `grab-it displays`, or text in its name |
| `--window <id or text>` | One window: an `id` from `grab-it windows`, or text in its app's name or title, ignoring case. With several matches, the frontmost wins. |
| `--region <x,y,w,h>` | A rectangle, such as `--region 0,0,800,600`, from the display that holds most of it |

And for `shot`, any of these:

| Option | What it does |
| --- | --- |
| `--delay <seconds>` | Waits before capturing, up to 60 seconds, such as `--delay 2` or `--delay 0.5` |
| `--max-width <pixels>` | Scales the shot down to at most that width, keeping its shape |

Options take their value after a space or an `=`: `--window=Firefox`.

Shots are saved to your save folder and Library like any capture, tagged **agent**. They aren't copied to the clipboard, and Quick Access and the editor don't open: a short **Captured by an agent** notice shows instead.

### Recording

```sh
grab-it record --window firefox --for 5
# {"path":"/home/me/Pictures/Grab-it/recordings/2026-11-17 09-00-00.mp4","durationMs":5012,"format":"mp4","id":43}
grab-it record --region 0,0,1280,720
# {"path":"/home/me/Pictures/Grab-it/recordings/2026-11-17 09-01-00.mp4","format":"mp4","recording":true}
grab-it stop
# {"path":"/home/me/Pictures/Grab-it/recordings/2026-11-17 09-01-00.mp4","durationMs":8400,"format":"mp4","id":44}
```

Without `--for`, `record` answers as soon as it starts, and the recording runs until `grab-it stop` or the **Stop** button on the [recording toolbar](/grab-it/recording/toolbar/). With `--for`, `record` waits for it to be saved and prints it, sooner if you stop it first. Only one recording runs at a time.

| Option | What it does |
| --- | --- |
| `--format <mp4 or gif>` | Records an MP4, the default, or a GIF. A GIF stops by itself after a minute. Until ffmpeg is ready, an MP4 is saved as a GIF: `format` says which. |
| `--fps <30 or 60>` | An MP4's frames a second; 30 if you don't say |
| `--cursor` | Draws the pointer in |
| `--for <seconds>` | Stops after that long, up to an hour |

These recordings ignore your [recording options](/grab-it/recording/options/) for sound, the webcam, the countdown, clicks and keystrokes: they're silent, with no webcam or countdown. They're saved to `recordings` in your save folder and to the Library, tagged **agent**, with a short **Recorded by an agent** notice instead of Quick Access.

### GIFs and contact sheets

`gif` and `frames` take any video file, such as the `path` of a recording.

```sh
grab-it gif "2026-11-17 09-00-00.mp4" --start 1 --end 4 --width 800
# {"path":"/home/me/Pictures/Grab-it/recordings/2026-11-17 09-02-00.gif","width":800,"height":450,"durationMs":3000,"id":45}
grab-it frames "2026-11-17 09-00-00.mp4" --count 9
# {"path":"/home/me/Pictures/Grab-it/originals/2026-11-17 09-03-00.png","width":1464,"height":848,"frames":9,"id":46}
```

`gif` makes an animated GIF, with a palette picked for the video, in `recordings` in your save folder:

| Option | What it does |
| --- | --- |
| `--start <seconds>` | Where the GIF starts in the video |
| `--end <seconds>` | Where it ends |
| `--fps <frames>` | Frames a second, up to 50; 10 if you don't say |
| `--width <pixels>` | Its width, keeping its shape; the video's own, up to 1280, if you don't say |

`frames` makes one PNG contact sheet: `--count` frames spread evenly through the video (12 if you don't say, up to 100), in a grid. It's how an agent, which can't watch a video, sees what a recording shows.

Both use Grab-it's ffmpeg, and fail with a message while it's still being set up. GIFs and contact sheets go in the Library tagged **agent** too. CLI screenshots, recordings, GIFs and contact sheets follow your [Save folder settings](/grab-it/reference/settings/#general).

:::note[Linux on Wayland]
Only your desktop may read the screen on Wayland, so `displays`, `windows`, `shot`, `record` and `stop` fail there with a message saying so. Use an X11 session. `gif` and `frames` still work.
:::

## Where Grab-it is

<Tabs syncKey="os">
<TabItem label="Windows" icon="seti:windows">

Where Grab-it is depends on which installer you used. The `-setup.exe` puts it in your user's programs folder:

```powershell
& "$env:LOCALAPPDATA\Grab-it\grab-it.exe" --open region
```

The commands print to the PowerShell or Command Prompt window you run them from, or to the program reading their output:

```powershell
& "$env:LOCALAPPDATA\Grab-it\grab-it.exe" shot --window Notepad
```

The `.msi` installs it for everyone on the PC, in Program Files:

```powershell
& "$env:ProgramFiles\Grab-it\grab-it.exe" --open region
```

To make a desktop shortcut, right-click the desktop, choose **New → Shortcut**, and enter the path for your installer followed by `--open region`.

</TabItem>
<TabItem label="macOS" icon="apple">

Run the program inside the app:

```sh
/Applications/Grab-it.app/Contents/MacOS/grab-it --open region
```

`open -a Grab-it` doesn't pass `--open` on to a Grab-it that's already running, so use the full path.

</TabItem>
<TabItem label="Linux" icon="linux">

The `.deb` and `.rpm` packages install `grab-it` on your `PATH`:

```sh
grab-it --open region
```

With the AppImage, run the AppImage itself:

```sh
./Grab-it_*_amd64.AppImage --open region
```

Bind it to a key in your desktop's keyboard settings if global hotkeys don't work there.

</TabItem>
</Tabs>

Building from source? `npm run tauri dev` takes the same targets after three `--`: `npm run tauri dev -- -- -- --open settings`. See [Developing Grab-it](https://github.com/kerwincarpede/grab-it/blob/main/docs/development.md).
:::
